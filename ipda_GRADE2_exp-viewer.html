Welcome to the GRADE2 RNAseq expression viewer

A standalone, browser-based visualisation tool

Explore the expression of genes and transcripts from your GRADE2 results: violins, heatmap, TAU Specificity, dot plots, correlation, sample metadata and STAR alignment QC.

Your data doesn't leave your computer. The files are read by your browser, and this page is not allowed to use the network, so there is nowhere for them to go. The Offline - no network access badge at the top right checks this every time the page opens.

What does this do?

Groups with fewer samples than this are left out of TAU Specificity. If a feature's median TPM is 0 in every group that remains, TAU cannot be computed (0/0) and the feature is shown as grey n/a, so very small groups can also remove features. The default 3 is the min_n = 3 of the R dot_plot() and specificity_strip() functions: a median, a fraction of samples above the cut-off, or a specificity score from one or two samples is not reliable. Set 1 to keep every group (a group of one sample then counts like any other). The figures on this page redraw as soon as you change the number.

What does this do?

The correlation is between features (genes/transcripts) across samples, on log2(tpm + 1), with pairwise complete observations. Spearman (default, as in the R script), Pearson and Kendall (tau-b; limited to 100 features) are offered. Panel order: strongest correlation first ranks the pairs by |correlation| in the samples you use, so it can change when you choose other groups; order of the ticked features keeps the same order whatever the groups, which makes sets easy to compare. Pairs to draw limits the scatter plots (9 per page). Min samples per group (5 in the R script, at least 3 here) applies to the group figures. Every choice is part of the plot: change any of them and the button turns blue; Plot correlation then adds a new set of tabs and keeps the earlier ones.

About

This page was created to visualise the results of the GRADE2 pipeline (General RNAseq Analysis for Differential Expression pipeline, version 2): github.com/isabela42/GRADE2. It is the interactive counterpart of pipeline step 083.

Everything runs inside your browser: no R, no server and no internet connection are needed.

Privacy and your data

Your files never leave your computer. This is enforced, not just promised:

  • The page is not allowed to use the network. A security policy built into the file tells the browser to refuse every connection (fetch, XHR, WebSocket, beacons) and every outside image, font, frame or script.
  • The lock badge in the header tests this each time the page opens, by trying to reach an outside address and checking that the browser refuses. Green means the browser enforces the policy and nothing was seen leaving; amber means either that the page tried and was blocked, or ("Offline by page code only") that the viewer you are using ignores the policy and only the page's own network lock is active; red means no protection is active (do not load private data then). The test uses a local data: address and never contacts the internet.
  • Click the badge for the Privacy & network check: the policy, the live counters, every web address written in the file and ways to verify it yourself (developer tools, going offline, searching the file for "http").
  • Preview windows: a viewer that embeds or rewrites the page (for example a preview inside a chat or editor) can make the browser ignore the policy tag, and the badge then says so. For the full guarantee, save the .html file and open it from your computer.
  • Files you choose are read in place by the browser, never copied. PDFs are written only to the place you pick. The only web address in the file is the GitHub link above, which is followed only if you click it.

Help

Quick start

  1. Main files: choose the metadata TSV and the TPM counts TSV. The counts file is scanned once (seconds, even for several GB) so single rows can be read quickly; wait for the green line.
  2. Gene names and id list: type or paste transcript/gene IDs, use the search box, and/or load a features TSV. Press Load features and plot: the button is light grey and locked while there is nothing new to plot, turns blue when everything needed is in, and turns blue again whenever you change an id, a file or a setting, to remind you to press it so the change takes effect.
  3. Look: every tab opens with the "All types combined" figure. Other views splits it into tabs (type, source, category ...).
  4. Typing ids: one per line; to attach a name write the id, press the Tab key, then the name (the Tab key types a tab inside this box; press Esc and then Tab to leave it with the keyboard). Typed ids and a loaded TSV are combined.
  5. Individual genes/transcripts: under each tab, open the picker, filter the loaded ones and plot the ones you want; Clear all removes them again.
  6. Save: tick the figures (checkbox left of each title) and press Export selected to PDF.

Input files

FileFormat
Metadata TSVTab-separated with a header. Required columns: sequencing-id, type, category, phenotype, phenotype-subtype, phenotype-identity, treatment. Also used when present: biological-system and source (metadata and STAR tabs).
Counts TSVTPM table from pipeline step 055: first two columns transcript and gene, then one column per sample named like the metadata sequencing-id. Version suffixes (.5) are ignored when matching IDs. Samples missing from either file are dropped.
Features TSVNo header; column 1 = transcript or gene ID, column 2 (optional) = the name shown on plots. Every ID is one feature: a transcript ID is that transcript, a gene ID is the gene with the TPM of all its transcripts added up (the log2(tpm + 1) is taken after the sum), as in step 083 of the R script. Transcript and gene IDs can be mixed, and a gene ID listed together with some of its transcripts gives the gene and those transcripts as separate features. A figure label is name (id).
STAR summary TSVOptional (STAR alignment QC tab). One row per sample with the numbers from each .Log.final.out; first column sequencing-id. Create it with the command in STAR summary table below.

The tabs

  • Violin - distribution per group: log2(tpm + 1) per group (violin + box + points); the number above each group is its sample count, also when the mean is zero. With several features the first figure shows the mean over all of them.
  • Heatmap - median per group, row z-score: median expression per group scaled per feature, colour scale centred on 0 (so average expression is pale), clustered with Ward.D2 (an overview without names above 1,500 features, see below). Bars show the category and the number of samples in each group.
  • TAU Specificity - which groups express it: TAU (0 = everywhere, 1 = one group only) and how expression is shared between groups; square tiles, "combined" or one row per feature. Groups with fewer than Min samples per group samples are left out, and a feature whose median TPM is 0 in every remaining group has no TAU (0/0): it is listed as a grey "n/a" row and counted in the note under the figure. Custom groupings with many small groups therefore lose features; lower Min samples per group at the top of the TAU Specificity tab or group more coarsely.
  • Dot plot - fraction expressing & median: dot size = fraction of samples at or above the TPM cut-off; colour = median expression.
  • Correlation - between features: choose the features (and optionally the groups) yourself, then Plot correlation: pairwise scatter plots first, then a correlation matrix, the similarity between groups and the strongest pairs across groups (see Correlation below).
  • Sample metadata - samples per group: stacked bars of how many samples there are per type, phenotype, subtype, identity and source, split by biological system and category.
  • STAR alignment QC - mapping metrics: input reads, uniquely mapped reads, mapping rate, read length, unmapped reads and chimeric reads per source and category, from the STAR summary table.

Transcripts, genes, or both

  • Transcript ids only: one feature per transcript (the counts row with that transcript id).
  • Gene ids only: one feature per gene: the TPM of every counts row of that gene is added up per sample, then log2(tpm + 1) is taken. A gene with one transcript is the same as that transcript.
  • Gene and transcript ids together: each id is its own feature, so a gene and some of its transcripts appear side by side (the gene is the sum, the transcripts are the parts). The Log says how many counts rows were matched and how many features they were collapsed into, like the R script. The exports have a rows_summed column and list the summed transcript ids.

Correlation

  • Nothing is drawn until you ask. Open the Correlation tab, tick 2 to 100 features in box 1 (filter the list, Tick shown, Clear), optionally tick groups in box 2, and press Plot correlation. The button is grey until there is something to plot and turns blue again whenever you change anything (features, groups, colour, method, minimum, panel order, number of pairs). Every plot adds a new set of tabs (#1, #2 ...) with its own choices, so you can compare methods or groups side by side; remove a tab with ✕ or use Clear all.
  • Pairwise scatter plots (first): one panel per pair of features, strongest |correlation| first (or in the order of the ticked features, see Panel order), 9 panels per page (several pages are tabs). The strongest-first order is worked out on the samples you use, so it can differ when you choose other groups. Each point is a sample (log2(tpm + 1) of the two features), coloured by the column you choose (type by default, like the R script); the black line is the least-squares fit; the title gives the correlation, n and p. Hover a point to see the sample (id, the colour value, plot_group, category and both values): the same sample is ringed in every panel of the page, so an outlier can be followed from pair to pair. Above 2,500 samples only 2,500 (a fixed random subset) are drawn per panel to keep the page fast; the correlation, the fit and n always use every sample, and the figure says so.
  • Samples and groups: pick a metadata column (plot_group, type, source, phenotype ...) and tick the groups to include; unticked = all samples. The same column defines the groups of the Groups figure (each group's median profile across the features, centred per feature, correlated between groups) and of Pairs by group (the strongest feature pairs, colour = correlation, size = -log10 of the BH-adjusted p; up to 50 features).
  • Matrix: the feature x feature correlation matrix of the selection, ordered by Ward.D2 clustering of 1 - correlation (numbers are written in for 15 features or fewer). Hover a cell for the correlation, n, p and the Benjamini-Hochberg adjusted p. Export pairs (TSV) writes the tidy table of the R script (method, group_by, group, feature1, feature2, n, rho, p, padj).
  • Statistics: Pearson and Spearman p-values use the t approximation, Kendall the tie-corrected normal approximation (cor.test(..., exact = FALSE)); constant features have no correlation (NA).

Long lists of genes/transcripts

  • Heatmap: up to 1,500 features it shows every name (rows are clustered up to 500 rows). Above that it becomes an overview of all features: gene names are not shown, the resolution is reduced (the features that share a pixel row are averaged; the figure is a raster image, also in the PDF), columns are clustered, and rows are ordered by the group where each feature peaks, which makes group-specific blocks appear as a staircase. Export row order (TSV) lists the features in the order they are drawn, with that group.
  • Random sample: above 1,500 features on the Heatmap tab (sample size 50 by default, up to 1,500) and above 300 on the Dot plot tab (300 by default), a box offers to plot a random sample with names. The seed makes it reproducible: leave it empty for a new sample each time, or type a number to repeat one; it appears in the figure title and in the file names. Export selected (TSV) saves the selected genes/transcripts; Export all + flag (TSV) saves every loaded gene/transcript with a selected column (yes/no).
  • Memory: every loaded feature takes about 8 bytes per sample in the browser (20,000 features x 7,000 samples is about 1.1 GB). The Log warns when a list is that large; use a shorter list if the page becomes slow.

Groups, highlighting and views

  • plot_group is the sample phenotype; for phenotypes matching a highlight term it becomes phenotype-subtype, and these groups are listed first.
  • Highlighted groups (all their samples match a highlight term): in violin plots the violins themselves are drawn in red; in the dot plot, heatmap, TAU Specificity and sample metadata plots the group label is red. A small key at the top right of each figure names the terms.
  • Min samples per group (default 3) is set at the top of the TAU Specificity and Dot plot tabs, where a short explanation is given; changing it redraws those figures at once. It leaves out of the dot plot and TAU any group with fewer samples, because a median, a fraction of samples above the cut-off, or a specificity score from one or two samples is not reliable. The value 3 is the min_n = 3 default of the R dot_plot() and specificity_strip() functions. Violins (which print the sample number above each group) and the heatmap show every group. Set it to 1 to keep all groups.
  • Exclude drops any sample with a matching value in any metadata column.
  • Other views splits a figure into one tab per Subtypes (sample type), Source or Treatment value. The Subtypes tabs end with one extra tab, cell-line names: the cell-line names (phenotype-identity) split by treatment. Click a tab, use the arrows, press ← / →, or swipe left/right (touch screens, two-finger trackpad swipes). Tick all selects every tab for the PDF.
  • Custom plot (last entry of Other views): choose the X axis, the Y axis (the figure's expression, or a numeric metadata column) and the facet columns / rows. X and facets offer the main metadata columns: plot_group, type, biological-system, phenotype, phenotype-subtype, phenotype-identity, full-description, treatment, source and category (a column with more than 300 different values is refused); this mirrors conditionX, conditionY, gridcol and gridrow of the R violin function. For heatmap, dot plot and TAU Specificity you choose the grouping column (and the bar/facet column). Each Add plot makes a new tab; ✕ on a tab removes it.
  • Zoom and expand: + / − on a figure zooms it (scroll inside to move). Expand opens a large window with zoom (buttons, Ctrl + mouse wheel, keys + − 0), drag-to-pan, arrows between tabs and Exit (or Esc).
  • Tutorial (top right, between the network badge and Theme): a guided tour of the page with a spotlight on each part. Before any data is loaded it can load a small made-up example so the figures are real; Esc ends the tour, the arrow keys move between steps.
  • Hover details (checkbox in the toolbar, on by default): on screen only, moving the mouse over a heatmap, dot plot, TAU Specificity strip, violin or sample metadata bar highlights the group (column) and, where there are rows, the feature (row) under the pointer and shows its details (n, median, fraction expressing, z-score ...). In the heatmap overview the details list the first features of that pixel row. Nothing of this is ever drawn into an exported PDF.
  • The ☰ button (top left) hides or shows the left menu to give the figures the full width; it also works on this page. About | Help (top right) opens this page and, while you are here, turns into ← Back to plots, so you can flip back and forth with one click.

Saving

  • In Chrome or Edge, Export opens the normal save dialog (suggested name grade2_YYYYMMDD_HHMMSS.pdf). Firefox and Safari save that name straight to Downloads.
  • PDFs are vector graphics on a white background whatever theme you use on screen; one figure per page.
  • Asking for more individual gene/transcript plots than the on-screen limit (default 50) offers to write them directly to a PDF.

STAR summary table

The STAR alignment QC tab needs one small table instead of thousands of log files. On the cluster, edit the first line of the block below (STAR_DIR = full path of the folder that holds one sub-folder per sample, each with a *.Log.final.out file), paste it into a terminal and press Enter. One awk command reads all the logs and writes star_summary.tsv in the folder you are in; then choose that file in section 4 of the left menu.

The sample name is the log file name without the salign-star-index_ prefix and the .Log.final.out ending; it must equal the metadata sequencing-id. If your files are named differently, adapt the ls pattern and the two sub() calls. A path containing spaces needs quotes around ${STAR_DIR}.
